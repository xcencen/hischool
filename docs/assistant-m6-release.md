## 当前操作入口

- 日常开发：Python 3.11 与分层 requirements，Vue 增量类型检查；依赖和缓存放 F:/my-campus-dev，沿用当前校园演示编排。
- 隔离验收：`scripts/verify_assistant.py --help`；从 Git 基线与显式文件清单生成 F 盘快照，只用合成数据、替身和临时数据库。
- 正式发布准备：独立 `compose.release.yaml` 与 `scripts/release_assistant.py`。后者只核对准入证据和镜像并输出可审阅计划，不能执行正式操作。不要将旧 `compose.yaml` 的自动初始化步骤用于正式发布。
- 管理员在 `/admin/assistant` 查看状态和维护试用名单；名单不赋予校园业务权限。管理员使用助手也需获准并确认。
- 用户在 `/app/assistant` 阅读并确认当前告知；撤回后后续外发停止，已完成历史仍归本人，历史删除为独立操作。已经发送的上游请求可能产生费用，仍需结算。

已提交版本的统一验收命令（产物目录必须尚不存在）：

```powershell
& 'F:/my-campus-dev/venvs/assistant-m1/Scripts/python.exe' -B scripts/verify_assistant.py --output F:/my-campus-dev/temp/m6-acceptance-new --browser 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe'
```

默认从 `git archive HEAD` 建立干净源码快照；验证未提交的指定文件时使用 `--snapshot-files <JSON文件列表>`，不复制整个工作区。Docker、Node、npm、浏览器、测试镜像、项目名、UI/代理端口均可通过 `--help` 中参数指定。默认从 `scripts/browser-tests/package-lock.json` 安装 Playwright 1.62.1，`--playwright` 仅用于显式复用同版本模块。
依赖安装使用 F 盘 npm 缓存且默认离线；首次缺包需先在 F 盘快照内用该锁文件运行 `npm ci --ignore-scripts --cache F:/my-campus-dev/cache/npm` 补齐包缓存，再执行验收。包仓库下载不属于模型调用，测试仍不得加载正式配置。未配置真实密钥也能完成全部必要检查；替身不能证明真实模型回答质量。

本地运行检查使用 `scripts/check_assistant_operations.py --docker <Docker路径> --project <当前项目> --compose-file <编排路径> --service api --service assistant-worker`；按启用服务追加 `--service campus-mcp` 等。仅从宿主机调用 Docker，API 无 socket。退出码0正常、1需处理、2无法评估，数据库故障不会显示为零积压。
正式清单使用 `release/assistant-manifest.example.json`；配置模板版本为 `m6-closed-v1`，须记录新/旧源码提交、全部镜像 registry digest 和回退镜像。验收报告须成功、提交一致、必要测试零跳过，实际应用镜像 ID 须等于报告的构建 ID；本地构建 ID 还需在获批发布流程中对应到 registry digest，不能将可变 tag 当作发布依据。

## 数据外发清单（待正式批准）

聊天提供商接收系统指令、当前用户输入、受限的成功历史上下文（默认八轮、48000字节上限）、六个工具的描述/参数结构与本轮白名单结果；不发送校园JWT、委托密钥、密码哈希或内部租约。

| 来源 | 可能进入聊天请求的数据 |
|---|---|
| 本人课表 | 日期范围、课程ID/名称/代码、课时ID、日期、起止时间、节次与地点、截断标记 |
| 公开通知列表/详情 | 通知ID、标题、正文截断、分类ID/名称、发布时间、分页信息 |
| 公开活动列表 | 活动ID、标题、正文截断、地点、时间/报名截止、名额/报名计数、分页信息 |
| 活动本人详情 | 列表字段及本人的报名状态、可报名/取消标记 |
| 学生手册检索 | 文档/版本/片段ID、标题、章节、PDF页序/印刷页码、正文片段、相似度、索引版本及证据不足标记 |
| 引用 | 服务端相对链接、来源编号和上述来源元数据 |

嵌入提供商接收知识检索 query。知识离线入库发送切分后的手册文本，属于既有独立知识流程，不由助手确认自动授权新增导入。原PDF不作为聊天附件发送。用户可能在自由输入中填写个人信息，告知必须说明该输入与历史上下文会发送给提供商；不能只描述工具字段。
实际出站字段以 `app/mcp/catalog.py` 白名单和 `app/assistant/graph.py` 消息为依据；本清单不授权外发任何正式数据。

## 正式启用门槛

发布负责人需提供：精确试用账号、获批告知版本/文本及提供商政策、允许外发字段、正式模型与嵌入账号价格/额度、备份/账本/确认记录留存、发布窗口与有效期、处理责任人、备份恢复证据、版本对应验收报告。
材料缺项、过期或哈希不符时准入检查失败，助手保持关闭。确认记录和最小财务元数据期限未定，本阶段不新增自动删除；七天正文擦除继续运行，备份留存也需要独立批准。

## 获批窗口内的操作顺序

1. 核对当前数据库版本、旧镜像与新镜像摘要、配置模板和测试报告，备份正式库并在独立库恢复核验。
2. 显式执行指定迁移至 `0007_assistant_access`（包含尚未执行的0006）；不seed，不更改历史迁移。
3. 保持双开关关闭，部署核验后的镜像，验证校园health/ready、关闭维护、财务与正文清理。
4. 单独发布获批告知：`python -B -m app.assistant.access --version <approved-version> --title <title> --file <approved-text-file> --approved`。该命令只保存告知，不启用助手。
5. 维护指定试用名单；用户自行确认；按独立获批的配置启用流程重新创建API/worker，进行额度内验证。
6. 越权结果、重复派发/记账、持续积压或数据不一致时关闭双开关，停止新任务，结算在途及释放预留后回退应用。

回退保留0006/0007表、确认与账本；旧镜像不认识灰度规则，必须持续关闭助手并验证派发为零。不在正式数据上downgrade。恢复备份前先保存故障账本与现场，依批准恢复点操作。
